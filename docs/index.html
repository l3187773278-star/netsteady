1. 它回答什么问题

  1. 我的跨境链路稳不稳？境内 → 境外这一段的丢包、尾延迟、断流，以及什么时候开始劣化。
  2. 我的出口 IP 干不干净？拿这个 IP 去访问 Claude / ChatGPT，属于哪一类风险特征。
  3. 具体哪些 AI 服务能过？14 个限制中国 IP 的服务逐个探测：解析到哪个 IP、那个 IP 归属哪里、握手多少毫秒、是被硬挡还是被 WAF 质询。
  4. 它们能不能看穿我在国内？单独查绕过代理的暴露面：IPv6、UDP/STUN、DNS 出口、系统时区与语言。

它不测带宽，也不做吞吐压测。跨境体验的瓶颈通常不是带宽，而是丢包和尾延迟。

2. 为什么不是 ping

如果只做 ping，这个工具没有存在意义。三个刻意为之的设计：

用 TCP 握手代替 ICMP。境外目标的 ICMP 常被限速或直接丢弃，ping 8.8.8.8 丢 20% 的时候网页往往还能正常打开。TCP SYN/SYN-ACK 的耗时更接近真实访问，而且不需要管理员权限。

双轨对照，而不是单目标。只看“境外某 IP 丢包 30%”判断不了是谁的问题。工具默认同时探测一组境内目标作为基线：境内也烂 = 你本地或宽带的问题；境内正常而多个境外目标同时劣化 = 国际出口的问题；只有一个境外目标烂 = 目标自身的问题。结论直接写在报告里。

按小时聚合，而不是一个平均值。跨境链路是规律性劣化的：晚高峰 20:00–24:00 丢包抬升，白天恢复。单次测量几乎看不出这个模式，按整点分桶后一眼就能看出来。

3. ip：出口 IP 体检

先用三家服务交叉确认你的出口 IP，再查它的归属、类型、DNS 出口和黑名单，最后逐个探测 14 个 AI 服务。

3.1 目标服务：解析 → 属地 → 连通 → 判定

  1. 解析：先问本机 DNS，如果拿到 198.18.0.0/15（TUN 代理的 fake-ip）就自动改走 DoH（依次尝试 dns.google → doh.pub → 阿里 → Cloudflare），拿到真实解析 IP
  2. 属地：一次 ip-api 批量查询，把这批 IP 的国家/城市一起取回来
  3. 连通：TCP 握手连两次取最小值（TUN 会缓存会话，第一次常被本地协议栈秒回，单次测量不准）
  4. 判定：看 HTTP 响应，区分四种结局
结果含义判据
✓ 可达服务接收了你的请求2xx，或 401/404/405（无凭据的正常拒绝）
✗ 区域拒绝明确因地区被挡响应体命中 unsupported_country、not available in your region 等
! WAF 质询IP 被判定为可疑，弹出人机验证403 + cf-mitigated: challenge / Just a moment...
✗ 连不上DNS 或 TCP 层面就断了解析失败 / 握手失败

WAF 质询和区域拒绝要分开看：前者说明 IP 不干净但服务本身对你开放（浏览器能过验证码，命令行过不去），后者是硬挡，什么客户端都没戏。

内置 14 个服务：Claude（网页 + API）、ChatGPT、OpenAI Codex、OpenAI API、Google Gemini（网页 + API）、Microsoft Copilot、GitHub Copilot、Perplexity、xAI Grok、Mistral、Midjourney、Cursor。

3.2 评分怎么来的

维度权重数据来源
出口 IP 一致性10Cloudflare trace / ip.sb / AWS checkip 三家交叉
地理一致性25ip-api / ip.sb / ipapi.co 三家国家字段是否一致
网络类型25hosting proxy mobile 标记 + ASN/组织名关键词 + 反查
DNS 出口20EDNS 回显的解析器出口是否与 IP 同区
链路可信度15ASN 完整性、反查、能否与目标站点建连
公共黑名单15Spamhaus / SpamCop / Barracuda（--dnsbl 开启）

权重和分数是启发式的，不等同于服务商内部风控结论。Claude 和 ChatGPT 的真实风控还包含账号历史、浏览器指纹、行为模式，这些从外部无法复现，任何号称能算出来的工具都是编的。

4. watch：持续监测

并发探测所有目标，实时刷新表格，结束时给出结论并可选输出 CSV / JSONL / HTML。

4.1 指标

指标含义为什么重要
丢包%探测失败占总探测数跨境链路上丢包比高延迟更致命，TCP 会因此反复重传
中位（P50）半数请求快于该值代表“通常的体感”
P95 / P99尾延迟决定你会不会突然卡一下，比平均值有用得多
抖动相邻 RTT 差的平均绝对值抖动大意味着路由或出口拥塞，语音/游戏会明显有感
最长断流连续失败区间的最长时长一次性断 30 秒比丢 5% 更难受
分时段按本地整点聚合的丢包/中位识别晚高峰规律

4.2 判定逻辑

境内对照组劣化                    → 本地网络异常（先查你自己的宽带）
境内正常 + ≥2 个境外目标劣化      → 跨境链路劣化（国际出口拥塞）
境内正常 + 只有 1 个境外目标劣化  → 单目标异常（目标自身限流/路由不友好）
全部正常                          → 跨境链路稳定

劣化的定义：丢包 ≥ 5%，或 P95/P99 同时超过中位的 2 倍且多出 40ms 以上。加绝对下限是为了避免在 10ms 的链路上把 21ms 误判成劣化。

4.3 输出文件

参数内容
--jsonl每次探测一行 JSON，追加写入，可中断续跑
--csv每个目标的汇总指标
--text终端看到的文本报告
--html单文件 HTML：内联 CSS + 内联 SVG，离线可看，无外部请求

5. leak：真实地址暴露面

ip 回答“这个 IP 像不像代理”，leak 回答一个更根本的问题：就算 IP 伪装好了，服务商有没有别的路子知道我实际在哪。

通道怎么测什么才算真泄漏
IPv6 出口请求一个只回 IPv6 的回显服务，再查这个 v6 的归属归属中国才是泄漏；归属和 v4 同国，说明只是代理的双栈地址
UDP / STUN自己组 STUN Binding Request 发到三台公共 STUN 服务器，解析回包里的 XOR-MAPPED-ADDRESS归属中国才是泄漏；地址不同但同国，多半是代理的 NAT 地址池
DNS 出口用 EDNS 回显看解析器从哪个国家出去和 IP 属地不一致就算可疑，因为 ECS 会把位置转告给 CDN
系统时区 / 语言读本机 UTC 偏移、时区名、locale浏览器用 Intl 和 Accept-Language 主动上报，矛盾时是硬指纹
CDN 接入点Cloudflare trace 里的 colo只作参考，说明流量实际落在哪个边缘节点

这里有个容易踩的坑：地址不一样 ≠ 泄漏。第一版工具直接把“STUN 回的地址 ≠ HTTP 出口地址”判成高危，结果全是误报——同一个代理的 NAT 池本来就会给出不同地址。改成比对归属地之后，两条高危降成了正常。

5.1 两条轴，别混为一谈

看不到你的真实地址，不等于这个 IP 就是纯净的。

问题判据命令
定位风险它能知道你在地球上哪个位置吗IPv6 / STUN / DNS / 时区语言leak
身份风险它能看出来你在用代理吗机房 ASN、hosting 标记、WAF 质询ip

一个家宽 IP 可能定位精准（没有任何泄漏通道），但它上过太多共享代理，照样被风控；反过来，一个机房 IP 可能完全不泄漏位置，却因为 ASN 写着 DigitalOcean 而被一眼看穿。这两项都过关，才叫“干净”。

6. 隐私

  • 工具不上报任何数据，所有请求直接打向目标站点和公开地理库，没有中转服务器。
  • 仓库里的示例地址一律使用 RFC 5737（203.0.113.0/24）和 RFC 3849（2001:db8::/32）文档保留段，不是任何真实机器的地址。
  • docs/demo.html 由 scripts/make_demo.py 生成，数据全部是合成的。
  • 你自己跑出来的输出包含真实出口 IP，贴给别人之前记得先打码。

7. 已知限制

  • anycast 目标测不到真实跨境 RTT。1.1.1.1、8.8.8.8 这类任播地址会就近接入，你可能只是在和本省/本国的节点握手。要测真实跨境路径，用 --target 指定一个固定位置的 IP。工具会在出现 < 8ms 的异常低延迟时主动提示。
  • 假 IP 会让测量失真。如果你的代理用了 TUN + fake-ip 模式（特征：域名解析到 198.18.0.0/15），所有 TCP 握手都由本地代理应答。工具会自动识别并改用 DoH 取真实解析 IP，但握手耗时仍然是“到你本地代理”的，不是物理跨境 RTT。
  • DoH 不是万能的。四个 DoH 端点都可能被同一层拦截；全部失败时表格里会显示本机解析结果（fake-ip），并在表下标注。
  • 不测 UDP / QUIC。纯 TCP 视角，QUIC 的表现可能更好或更差。
  • 单机视角。没有分布式探针，只能说明“从我这台机器看”。
  • DNSBL 多数不可用。公共 DNS 会被 Spamhaus 等拒绝查询，该维度常直接跳过并自动归一化权重。
  • 纯净度评分是启发式。它衡量的是“公开资料显示的特征”，不是服务商的裁决。
